## 对应实现方案

里程碑中的诊断流程如下：

1. 回放既有 cross-anchor 实验产生的 `confirmed-crosses.json`，不重新生成红叉锚点。
2. 使用整页 RapidOCR 文本框和红色版面组件生成编号候选框。
3. 每个红叉锚点保留不超过三个候选题框，候选框与供模型观察的上下文框分开。
4. 使用本地红色中心支持、页底数字 OCR 等规则做保守锚点复检。
5. 本地确定性事件优先选择标准候选框，并按 OCR 行、相邻事件位置执行原子边界裁断和重复事件审计。
6. 可选 MiniMax 请求仅核验红叉形状真假，不选择题目候选，也不生成坐标。
7. 离线模式不请求 MiniMax，专门评估本地候选上限、确定性事件和边界规则。

该方案的重要约束是：CV 组件数不等于错题数，OCR 文本相似和 bbox 重叠只能作为审计信号，不能证明两个相邻事件属于同一道题。

## 里程碑结论

这个里程碑不是最终识别方案，而是一个明确的技术分界点：

- 已证明本地确定性边界计算可以在 page33～35 上保持完整召回，并以极低计算成本消除这些页面的兄弟题侵入。
- 也已证明“围绕每个锚点生成局部候选，再用 IoU/OCR 相似做原子化”的方法无法稳定泛化到 page5、page7、page20，尤其无法处理 page20 的复杂版面。
- 后续不再继续调整原子化阈值，也不再让 MiniMax 自由生成几何边界。
- 下一阶段改为：本地 CV + OCR 先对整页生成稳定的全局 `question_unit_id`，红叉锚点随后映射到既有单元；MiniMax 作为语义裁判核验锚点、判断错题、选择单元并补充漏检，但只能引用本地编号，不能生成坐标。
- 用户主动“重新识别”时保留两轮结果，以稳定 `question_unit_id` 取并集合并；不同题目单元不得只因框重叠或 OCR 相似而去重。
