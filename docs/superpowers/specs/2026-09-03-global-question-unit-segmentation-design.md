# 全局题目单元分割与重试合并诊断设计

## 1. 背景与结论

现有诊断已证明：CV 红叉锚点的召回可接受，但 MiniMax 在自由生成错题边界或从局部候选中选择时存在明显波动；单纯继续调整 LLM2 prompt、批次或阈值，不能稳定改善召回与误报。

下一步不再让 LLM 生成坐标。先由本地 CV + OCR 在整页范围生成确定性的 `question_unit_id` 和题目单元边界，再把红叉锚点映射到少量题目单元。MiniMax 后续只负责在编号单元中判断错题归属。用户主动“重新识别”时，保留两轮结果，并按稳定题目单元身份做本地并集合并。

## 2. 范围

- 仅修改诊断脚本、诊断配置和相关单元测试，不修改生产识别流程。
- page33、page34、page35 是开发集，只允许用这三页调整本地分割规则和配置。
- page5、page7、page20 是冻结后的验证集；在开发配置冻结前不得用于调参。
- 第一阶段完全离线、本地运行，不增加 LLM 请求。
- 只有第一阶段达到验收门槛后，才进入 MiniMax 编号选择和两轮重试合并实验。

## 3. 目标与非目标

### 目标

1. 整页先生成与红叉锚点无关、重复运行完全一致的题目单元。
2. 每个红叉锚点只映射到 1～3 个已有题目单元，不再围绕锚点临时生成自由边界。
3. 相邻上下题、左右题具有不同的稳定单元身份，避免 page33/page5 已观察到的兄弟题侵入和错误合并。
4. MiniMax 只返回单元编号或 `none`/`uncertain`，不生成、修改坐标。
5. 两轮识别结果取并集；同一题目单元合并证据，不同题目单元不得仅因框重叠或 OCR 相似而合并。
6. 允许少量误报，但任何锚点和已选择单元都不得被静默删除。

### 非目标

- 本轮不追求 OCR 文本完全正确。
- 本轮不要求 MiniMax 每次返回一致。
- 本轮不修改生产 API、数据模型或小程序交互。
- 本轮不通过增加固定 LLM 请求次数换取召回。
- 本轮不使用人工真值参与运行时分割或选择。

## 4. 总体数据流

```text
原始整页图
  ├─ 本地版面线索：红色表格/分隔线、轮廓、空白带
  └─ 本地 OCR：文本行框、行中心、行间距
          ↓
全局行带与列带
          ↓
确定性题目单元 question_unit_id + unit_bbox
          ↓
CV 红叉锚点映射到每个锚点的 1～3 个 unit_id
          ↓
第一阶段：用真值只做离线 oracle 审计
          ↓（本地门槛通过后）
MiniMax 作为语义裁判：核验锚点、判断错题、选择 unit_id、补充漏检
          ↓
按 question_unit_id 去重；重新识别时合并两轮结果
```

## 5. 本地全局题目单元

### 5.1 全局分割原则

- 先按整页坐标建立行带和列带，再考虑红叉；锚点不能改变单元边界。
- 行边界优先使用稳定的印刷/表格分隔线和明显空白带；OCR 行中心与行间距用于补充。
- 列边界优先使用表格竖线、长期空白走廊和 OCR 行的水平分布。
- 拼音、题干、作答、批注可能占多行；多行归入同一单元时必须受全局行带约束，不能跨越已确认的兄弟题边界。
- 安全上下文框与最终单元框分离：安全框可用于给 LLM 看更多上下文，但最终事件只能引用某个确定的 `unit_bbox`。

### 5.2 稳定身份

每个题目单元输出：

- `question_unit_id`：由页内确定性的分区、行序、列序组成，例如 `U-S01-R03-C02`。
- `unit_bbox`：归一化坐标。
- `context_bbox`：仅供模型观察的安全上下文框。
- `ocr_line_ids`：归属该单元的 OCR 行编号。
- `layout_evidence`：使用了哪些表格线、空白带或 OCR 线索。
- `risk_flags`：边界不完整、多行歧义、无 OCR 等审计标记。

同一原图、同一配置重复运行时，上述 ID、边界和顺序必须完全一致。

## 6. 锚点到题目单元的映射

每个 CV 红叉锚点对所有既有单元计算本地排名，依据仅包括：

- 锚点是否落在 `unit_bbox` 或 `context_bbox` 内；
- 锚点与单元边界/中心的归一化距离；
- 行带、列带是否兼容；
- 红色标记与表格结构的局部关系。

每个锚点保留排名最高的 1～3 个单元编号。候选数量、距离上限和安全框扩展比例放入独立配置文件并写明含义，不写死在代码中。

如果没有可靠映射：

- 保留该锚点；
- 输出 `unassigned_anchor` 或 `needs_review`；
- 不允许以低置信度为理由静默删除。

## 7. MiniMax 语义裁判的职责

“只能引用编号”约束的是几何输出，并非削弱模型的语义职责。本地阶段通过后，模型每页接收：

- 带编号题目单元的整页图或拼图；
- 每个红叉锚点允许选择的 1～3 个 `unit_id`；
- 红圈、老师批注、学生答案和改正内容等辅助证据；
- 明确的结构化输出枚举。

MiniMax 负责：

- 判断 CV 锚点是 `valid`、`invalid` 还是 `uncertain`；
- 在允许的编号单元中判断红叉属于哪一道题；
- 结合实际答题内容判断该题是 `incorrect`、`correct` 还是 `uncertain`；
- 判断本地边界是 `complete`、`too_narrow`、`sibling_intrusion` 还是 `uncertain`；
- 在同一次整页请求中扫描未绑定锚点的编号单元，用 `supplemental_wrong_unit_ids` 补充明显错题，弥补 CV 漏检。

模型不得返回坐标，也不得创造不存在的单元。红叉仍是主要锚点，红圈、批注和答案内容作为语义证据。若模型全部确认，报告必须单独记录 `all_selected`；不得把“全部选择”视为默认成功。

建议的核心输出字段为：`anchor_id`、`anchor_validity`、`selected_unit_ids`、`question_status`、`boundary_fit`、`evidence`、`confidence` 和整页级 `supplemental_wrong_unit_ids`。其中只有编号选择影响自动事件集合；解释性字段用于审计、重试合并和后续产品判断。

## 8. “重新识别”的两轮合并语义

用户主动重新识别时，不覆盖第一轮：

1. 两轮选中结果按 `question_unit_id` 取并集。
2. 同一 `question_unit_id` 合并锚点、模型轮次、置信度和证据来源。
3. 不同 `question_unit_id` 永不因 bbox IoU 或 OCR Jaccard 相似而合并。
4. 同一单元内部可用 OCR 指纹辅助识别重复内容，但 OCR 指纹不能跨兄弟单元充当主键。
5. `none`/`uncertain` 只记录该轮判断，不得删除另一轮已经保留的单元。
6. 冲突和新增结果分别输出，供后续产品交互决定是否提示用户；本轮仅验证合并数据语义。

这直接规避 page5 中两个上下相邻真实错题因框重叠和共享 OCR 行而被错误合并的问题。

建议新增独立实验脚本，不覆盖现有 selector 结果：

- `scripts/diagnose_global_question_units.py`

- `tests/unit/test_diagnose_global_question_units.py`

## 10. 分阶段验收门槛

### 阶段 A：本地单元与映射，只用 page33～35

- 相同输入连续运行两次，单元 ID、bbox、锚点候选列表完全一致。
- 三页候选 oracle 的真实错题召回均为 1.0。
- 三页兄弟题侵入为 0。
- 每个锚点最多映射 3 个单元；无静默丢失锚点。
- 记录 OCR、版面分割、锚点映射的独立耗时；不增加任何 LLM 请求。

未达到上述门槛时，只修本地单元生成或锚点映射，不进入 MiniMax prompt 调试。

### 阶段 B：冻结配置后验证 page5、page7、page20

- 不改配置、不参考验证集真值调整规则，只运行一次。
- 候选 oracle 真实错题召回目标为 1.0；任一漏题都必须定位到单元生成或锚点映射，不得用 LLM 兜底掩盖。
- 兄弟题侵入不得高于现有基线，且不得因去重把两个真实兄弟题合并。
- 若验证失败，记录泛化失败类型；回到设计层修正通用规则后，重新冻结并重新定义一次完整验证轮次，禁止逐页补丁。

### 阶段 C：MiniMax 单轮与重试并集

- 仍保持每页单轮一次编号选择请求，不增加固定第二轮；第二轮只由用户主动重试触发。
- 分别报告第一轮、第二轮、两轮并集的真值召回和误报。
- 两轮并集召回不得低于任一单轮；不同题目单元不得被错误去重。
- 与现有方案比较平均耗时和最差耗时；本地分割耗时单独列出。

## 11. 防过拟合措施

- 严格区分开发集 page33～35 与验证集 page5/page7/page20。
- 配置在验证前冻结，并在产物中记录配置文件哈希。
- 运行时代码不读取 expected count、truth region 或页面名称。
- 所有阈值是版面比例或 OCR/几何通用量，不使用某页专属坐标。
- 报告 grid-only、OCR-only、combined 三种证据的消融结果，确认收益来自通用结构而非单页偶合。
- 不以 MiniMax 某一次随机结果作为本地阶段通过标准。

## 12. 错误处理与保守策略

- OCR 缺失：使用表格/空白带生成单元，标记 `ocr_missing`，不得删除锚点。
- 表格线缺失：使用 OCR 行带与空白走廊，标记 `grid_missing`。
- 无法形成唯一单元：给锚点保留多个候选并标记 `needs_review`，仍不生成自由坐标。
- 多个锚点映射同一单元：允许合并为一个事件并保留全部锚点证据。
- 一个锚点映射多个单元：交给编号选择阶段；本地层保持候选集合。

## 13. 测试策略

实现遵循测试先行，至少覆盖：

1. 相邻上下题生成不同稳定 ID，不能因共享 OCR 行或高 IoU 合并。
2. 相邻左右题生成不同列身份。
3. 多行题干/拼音/作答归入同一题目单元。
4. 锚点最多得到 3 个候选，且无候选时进入审计而非丢失。
5. 相同输入重复运行结果字节级稳定。
6. 两轮相同单元合并证据，不同单元保持独立。
7. 第二轮 `none`/`uncertain` 不会删除第一轮结果。
8. 诊断脚本不会读取真值参与运行时决策。

## 14. 实施顺序

1. 新增阶段 A 的纯本地单元生成、锚点映射和 oracle 报告，先只跑 page33～35。
2. 本地验收通过后冻结配置，再跑 page5/page7/page20。
3. 只有六页的本地候选层达到门槛后，复用编号 selector 接入 MiniMax。
4. 最后用已有归档和服务器新结果验证两轮并集去重、准确率和耗时。

任何阶段失败都停在该层修正，不跨层通过更多 LLM 请求补偿。
