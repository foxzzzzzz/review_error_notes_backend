**Tech Stack:** Python 3.12（本地已有虚拟环境）、NumPy、OpenCV、Pillow、RapidOCR、现有 MiniMaxVisionClient（仅服务器显式运行）。

**Spec:** 工作区根目录 docs/SPEC.md 的“2026-09-05 收敛验收补充”，以及本会话确认的区域＋内容联合口径。

- 代码位于 backend-main-benchmark 现有 linked worktree；不触碰 old_solution 和既有未跟踪实验。
- 本地允许 CV、OCR、离线评估、样本裁图及模拟响应测试，不发真实 MiniMax 请求。
- 配置参数统一写入带说明的外部 JSON；报告记录图像、配置、代码哈希及运行环境。
- 26 页、69 道题均已参与过分析，称回归集；0905 的原始首次测试结果保留为历史盲测，不能调参后继续称同版本盲测。
- 现有真值是错题区域，不是红叉坐标，也没有内容答案。导出的参考表必须标为待人工审核，OCR 不得自动升级为真值。
- “人工框内容实验”仅验证局部能力上限；脚本记录请求与解析耗时，原图准备及实验文件保存不在该计时内，不能称为生产端到端时间。
- 服务器验证未返回前，不能宣称联合准确率、模型内容能力或生产 30 秒目标已达标。

## 验收定义

- 联合正确召回 = 唯一匹配的真实错题中，完整区域、题干/拼音、学生原始作答、正确答案、解析全部正确的数量 / 所有真值数量。
- 误报 = 不属于真实错题的输出＋重复输出；误报率分母是全部输出。错框或内容错误另计入联合失败与无效输出比例。
- 零输出且有真值时召回为 0，误报率为 null，不能通过整体验收；零真值页面须单报假输出数。
- 解析审核使用可接受语义及错误规则，不要求逐字相同；不把“粗心”等无法从图片证实的心理推断视为合格解析。
- 时间 = 保存完成 - 上传完成 - 排队等待；缺失任一计时数据不能通过完整耗时门槛。超时页不从质量分母删除。
- 95%、10%、30 秒只作最终门槛；局部实验预算：候选覆盖 99%、条件定位 98.5%、条件内容 98%，模型阶段预算为实验目标而非已实现保证。
